Six ordered migrations under `supabase/migrations/` form an incremental database evolution:
- `0001_schema.sql` creates the `public` schema tables (business/outlet, catalog: supplier/inventory_item/product/product_variant/recipe_line, customer, sales_order/order_item/payment, stock_movement/purchase/purchase_line/expense, audit_log/ai_event/holiday_calendar), the `private` schema with `touch_updated_at`, and enables `pg_trgm`.
- `0002_rls.sql` enables Row Level Security on every table via a looped `alter table ... enable row level security / force row level security`, defines `private.is_member` as a `security definer` helper, and declares per-table policies grouped by domain (tenancy, catalog read/write, customers, ledger read-only, expenses, audit/AI, shared holiday data).
- `0003_functions.sql` introduces all transactional entry points (`create_business`, `complete_sale`, `record_purchase`) plus private helpers (`stock_of`, `segment_for`, `rupiah`, `sale_lines`, `refresh_hpp`, `resolve_outlet`); every write path is `SECURITY DEFINER` and re-checks membership before mutating ledger tables.
- `0004_workspaces.sql` adds workspace onboarding (`create_workspace`), team management (`list_team_members`, `add_team_member_by_email`), product/inventory save APIs, and tenant-integrity triggers (`check_variant_tenant`, `check_recipe_tenant`, `check_inventory_supplier_tenant`).
- `0005_production_hardening.sql` hardens concurrency and correctness: idempotency keys on purchase, NaN/Infinity guardrails on numeric checks, `business_id_immutable` trigger across all tenant-scoped tables, `catalog_business_lock` trigger to serialize catalog writes per business, and hardened versions of `complete_sale`/`record_purchase`/`save_inventory_item`.
- `0006_storage.sql` registers the public `menu-images` Supabase Storage bucket.

Dependency direction is strictly forward: later migrations only `CREATE OR REPLACE` or augment objects from earlier ones; no file imports another. The `private` schema holds internal helpers (not exposed to clients), while `public.*` functions are the only client-facing API surface after explicit `grant execute ... to authenticated` blocks at the end of each migration.
