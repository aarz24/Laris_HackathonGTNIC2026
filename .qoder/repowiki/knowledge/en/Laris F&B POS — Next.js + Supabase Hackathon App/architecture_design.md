The root is a Next.js 15 app (turbopack) that wires two child concerns together: `database_migrations` (Supabase SQL migrations defining the multi-tenant RLS schema, PL/pgSQL functions like `complete_sale`, and storage buckets) and `dev_scripts` (Node scripts for seeding, RLS isolation testing, CSS tokenization, and voice-parser evaluation). Cross-child wiring happens via environment variables declared in `implementation_plan.md` (`NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `GOOGLE_GENERATIVE_AI_API_KEY`) consumed by both the Next runtime (`next.config.ts` whitelists `*.supabase.co` images) and the Node scripts. The UI's existing `BusinessState` snapshot shape is the contract between the old browser-only code and the new server-side data layer, so adding Supabase does not require rewriting the UI.
