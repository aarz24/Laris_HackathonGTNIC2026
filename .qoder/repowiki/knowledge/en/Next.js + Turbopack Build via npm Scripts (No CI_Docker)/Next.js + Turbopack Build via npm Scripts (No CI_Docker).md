## Build System Overview

Laris uses a minimal, convention-driven build setup centered on **Next.js 15** with **Turbopack** enabled for both development and production builds. There is no Dockerfile, no Makefile, no CI pipeline YAML, and no cross-compile toolchain in this repository.

### Toolchain & Entry Points

- **Package manager**: `npm` (lockfile present as `package-lock.json`).
- **Runtime**: Node.js with `--experimental-strip-types` used to run TypeScript directly without a separate compilation step for scripts and tests.
- **Framework build**: `next build --turbopack` (production) and `next dev --turbopack` (development), configured via `next.config.ts` which sets `turbopack.root = process.cwd()`.
- **TypeScript**: `tsconfig.json` plus `next-env.d.ts` generated by Next; `eslint.config.mjs` drives linting.
- **Styling pipeline**: PostCSS + Tailwind v4 (`postcss.config.mjs`, `tailwindcss: ^4`, `@tailwindcss/postcss: ^4`).

### npm Scripts (`package.json`)

| Script | Command | Purpose |
|---|---|---|
| `dev` | `next dev --turbopack` | Local development server |
| `build` | `next build --turbopack` | Production bundle |
| `start` | `next start` | Serve the built output |
| `lint` | `eslint` | Lint via ESLint 9 config |
| `test` | `node --test --experimental-strip-types src/lib/laris-data.test.ts` | Runs the single unit test file using Node's built-in test runner |
| `db:seed` | `node --experimental-strip-types --env-file=.env scripts/seed.ts` | Seeds Supabase demo tenants |
| `test:rls` | `node --test --experimental-strip-types --env-file=.env scripts/rls.test.ts` | Row-Level Security isolation tests against Supabase |
| `eval:voice` | `node --experimental-strip-types --env-file=.env scripts/eval-voice.ts` | Voice-to-cart benchmark (uses `evals/voice.jsonl`) |

All script/test invocations use `--experimental-strip-types` so TypeScript files execute directly under Node — there is no intermediate `.js` artifact produced by a separate `tsc` step.

### Environment & Secrets

- `.env.example` documents required variables; `.env` holds local secrets.
- Scripts that touch Supabase or AI providers require `--env-file=.env` to load them at runtime.
- The seed script supports a demo mode gated by `LARIS_DEMO_EMAIL` / `LARIS_DEMO_PASSWORD` (documented in `README.md`); the README explicitly warns not to enable demo credentials on public production deployments.

### Deployment Surface

The PRD states the target is **Vercel + Supabase deployed on day 1**, but no Vercel configuration, GitHub Actions workflow, Dockerfile, or containerization exists in the repo. The deployable artifact is the Next.js build output produced by `next build --turbopack`. Database schema changes are managed through Supabase migrations under `supabase/migrations/` (numbered SQL files).

### Conventions Observed

- Development and production builds both go through Turbopack (`--turbopack` flag on both `dev` and `build`).
- All Node-side code (scripts, tests, server actions) is written in TypeScript and executed directly via `node --experimental-strip-types`; there is no `tsc` build step in any npm script.
- Test files live alongside the code they exercise (e.g. `src/lib/laris-data.test.ts`) and are discovered/run via Node's built-in `--test` runner rather than Jest/Vitest.
- Supabase operations are isolated per tenant via RLS policies tested by `scripts/rls.test.ts`.
- No version pinning of Node itself is present in the repo (no `.nvmrc`, no `engines` field in `package.json`).
